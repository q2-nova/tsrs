# TSRS

TSRS helps the [Q2 player app](https://github.com/q2-nova/q2-player) on the
Shanling Q2 portable music player connect to music servers on a Tailscale
network. This repository builds `tsrsd`, the background service that forwards
the app's connections and handles Tailscale sign-in, sign-out and status.

If you're contributing to the daemon, start with the [native build and
tests](#native-build-and-tests). They run on Linux without a Q2 or a Tailscale
account. There is no stable standalone download. The [Q2 operating
system](https://github.com/q2-nova/q2-os) packages the daemon with the player.

`tsrsd` is built on [tailscale-rs](https://github.com/tailscale/tailscale-rs).
The player supervises the daemon and uses its HTTP proxy and Unix socket
LocalAPI. The Q2 OS installs it at `/usr/libexec/q2-network/tsrsd`.

## Native build and tests

Use Linux with Python 3, Git, Rust and a C toolchain. Preparation clones the pinned upstream commit and applies `tailscale-rs.patch` in `build/tailscale-rs`. `prepare --tailscale-source /path/to/repo` can use a local Git repository containing that commit. Every build verifies the upstream commit and the applied patch. Cargo locks the registry dependencies in `Cargo.lock`. tokio comes from branch `q2/1.54.1` of the [q2-nova/tokio](https://github.com/q2-nova/tokio) fork, pinned by commit, which wakes the runtime thread once per timer expiry.

```sh
python3 build.py prepare
python3 build.py fetch
python3 build.py test
python3 build.py host --out build/host
build/host/tsrsd version
```

The native tests use local fixtures for the CLI, proxy and daemon state. They require no tailnet account. `fetch` populates the Cargo cache and the test and build commands use it offline. Run `python3 build.py upstream-test` for the patched runtime and DERP dependency suites, which may fetch their own dev-dependencies.

GitHub Actions runs `test_release.py`, `ci/test_smoke.py`, the native tests, and the [smoke test](#smoke-test) and [control test](#control-test) of a host build on every pull request and push to `main`.

## Build for the Q2

Use a relocated SDK generated by [q2-os](https://github.com/q2-nova/q2-os), the Q2 OS Rust linker shim, a completed compiler build from [q2-toolchain](https://github.com/q2-nova/q2-toolchain), and Cargo from the pinned nightly. The compiler work directory contains `install/x2000-toolchain.json`. The Q2 build checks that receipt and requires committed TSRS sources. Run from the TSRS checkout.

```sh
rustup toolchain install nightly-2026-11-12 --profile minimal
python3 build.py q2 \
  --sdk /path/to/relocated-sdk \
  --toolchain-repo /path/to/q2-toolchain \
  --compiler-work /path/to/q2-toolchain/build/x2000-toolchain \
  --rust-link /path/to/q2-os/os/rust-link.py \
  --out build/q2
python3 build.py admit --out build/q2
```

The output directory contains the stripped MIPS ELF `tsrsd`, its `result.json` build record, `size.json`, and the debug companions under `symbols/`. Pass the directory to the Q2 OS composer with `--tsrsd build/q2`. Each build requires an unused output directory. Keep the companions with the exact shipped binary for diagnostics.

## Smoke test

`ci/smoke.py` starts a built `tsrsd` with the command line q2nd passes, a fresh state directory and a control URL that refuses connections, so it needs no network or tailnet account. It checks that:

- the LocalAPI status (`GET /localapi/v0/status` on the Unix socket) reports `BackendState` `Starting` with this checkout's version, no login URL and no addresses, and after 20 s the health sentence `Waiting for the Tailscale control server`;
- the CLI shim's `tsrsd status` prints `Starting`;
- the HTTP proxy forwards a request to a local origin;
- the daemon creates `keys.json` with mode 0600 in the `tailscale-rs` directory beside the `--statedir` q2nd passes;
- the daemon log shows no restart, panic or local socket or key file error.

It then stops the daemon with SIGTERM and requires it to exit by that signal. A run takes about 20 s.

```sh
python3 ci/smoke.py --tsrsd build/host/tsrsd
python3 ci/smoke.py --tsrsd build/q2/tsrsd --qemu /path/to/qemu-mipsel \
  --sysroot /path/to/relocated-sdk/mipsel-buildroot-linux-gnu/sysroot
```

With `--qemu` the daemon and the shim run under user-mode QEMU with `-cpu P5600` and the SDK's sysroot. Use `bin/qemu-mipsel` from the Q2 QEMU release of q2-toolchain (`qemu-linux-x86_64.tar.gz`). `python3 ci/test_smoke.py` tests the smoke's checks on generated status documents and logs.

## Control test

`ci/control.py` runs a host build on the generated tailnet of `tools/pgo.py`
(Headscale 0.29.7 with its DERP server, a host peer built with the `pgo-peer`
feature, everything on 127.0.0.1) in a new user and network namespace. It
checks that:

- a node with fresh state started while control refuses connections stays
  `Starting`, then signs in and reaches the peer once control starts, in the
  same process;
- a signed-in daemon whose control server stops for 40 s neither exits nor
  restarts, and within 30 s of control's return reaches the peer again with a
  new control connection.

The device keeps its registration, peers and data plane while control is
away and reconnects with backoff of 0.5 s to 10 s; the watchdog does not count
control silence while it reconnects. A run takes about 100 s and downloads the
pinned Headscale into `build/pgo-downloads` once.

```sh
CARGO_TARGET_DIR=build/target-pgo-peer cargo build --release --offline --locked --features pgo-peer
python3 ci/control.py --tsrsd build/host/tsrsd --peer build/target-pgo-peer/release/tsrsd
```

## Profile-guided build

Release builds of tsrsd are profile-guided. `tools/pgo.py profile` takes the
`build.py q2` inputs and the Q2 fork's `qemu-mipsel`. It builds an
instrumented daemon (`build.py q2 --profile-generate`) and a host tsrsd with
the `pgo-peer` feature, then trains the instrumented daemon on a generated
tailnet in a new user and network namespace. Headscale 0.29.7, pinned by
URL and SHA-256 in `tools/pgo.py`, provides control and its built-in DERP
server with a generated certificate authority. The host tsrsd is the peer
and forwards its tailnet port 80 to a generated content server. Everything
listens on 127.0.0.1; a dummy link with a documentation address carries the
default route. The workloads are sign-in, name lookups, streaming in the
player's fetch-ahead pattern, a bulk download, idle keepalives, a link drop
and return, DERP-only paths, control loss and error replies. The daemon is
stopped rather than exiting, so the instrumented build counts in continuous
mode. `train --daemon PATH` runs the same workloads on another Q2 build, such
as the profile-guided release.

```sh
python3 tools/pgo.py profile --sdk /path/to/relocated-sdk \
  --toolchain-repo /path/to/q2-toolchain --compiler-work /path/to/compiler \
  --rust-link /path/to/q2-os/os/rust-link.py --qemu-user /path/to/qemu-mipsel \
  --out build/pgo
python3 build.py q2 ... --profile-use build/pgo/tsrsd.profdata --out build/q2
python3 build.py q2-test ... --profile-use build/pgo/tsrsd.profdata \
  --qemu-user /path/to/qemu-mipsel --out build/q2-tests
```

`build/pgo/receipt.json` records the profile's SHA-256, the compiler, the
feature set, the coverage summary with the named hot paths (packet filter,
WireGuard, DERP, proxy copy loop), each phase and the training minutes.
`build.py q2 --profile-use` refuses a receipt with another compiler or
feature set and copies it into `result.json`. `q2-test` builds the daemon's
tests and the dataplane's TSMP reject and transport queue tests for the Q2 with the same profile
and runs them under `qemu-mipsel`. The test harness unwinds, as Cargo builds
tests; the rest matches the release build. Training restarts a daemon that
exits, as q2nd does. Unprivileged user namespaces must be
allowed; on Ubuntu set `kernel.apparmor_restrict_unprivileged_userns=0`.
The DERP-only phase needs `nft`.

## Release the target daemon

The entries in [release-lock.json](release-lock.json) select tagged
releases of q2-os, q2-toolchain and the Q2 QEMU. Push a tag such as
`v0.1.0-rc.1` once those releases are available. GitHub Actions downloads
their SDK, compiler and emulator, checks the downloaded assets, runs the
tests, profiles and builds the daemon, runs its tests built with the same
profile and the smoke test on it under `qemu-mipsel`, and publishes
`tsrsd-q2.tar.gz`, its checksum, `q2-tests.json` and the dependency source
bundle on the daemon’s GitHub prerelease. The archive's `result.json`
carries the profile receipt. A manual dispatch exercises the same build.
Private dependency repositories require a contents-read credential stored as
`Q2_COMPONENTS_READ_TOKEN`.
